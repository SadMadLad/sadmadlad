Network Programming

My Glossary of concepts and coding terms for network programming.

Terms and Definitions

  • accept The accept returns the next completed request from the completed connection queue. Takes in server socket file descriptor, and other arguments to return the protocol address of the connected peer process. If the connection is accepted successfully, it returns non-negative value, else -1.
  • ANSI: Stands for American National Standards Institute.
  • ARP: Stands for Address Resolution Protocol. Maps IP Address to MAC Address.
  • bind This functions assigns a local protocol address to a socket. Inputs are the socket file descriptor, socket structure, and size of the structure. Returns 0 if bound fine, something else in case of error (-1).
  • BPF: Stands for BSD Packet Filter. Allows programs to inspect raw packets in datalink layer.
  • connect Takes in the socket file descriptor, pointer to socket address structure and size of the structure as the argument and returns 0 if the connection works fine, else it is erroneous.
  • DLPI: Stands for Data Link Provider Interface. Similar to BPF but different OS family.
  • Four-way handshake Used by SCTP to establish associations.
  • Full-duplex: Means two devices can send and receive data at the same time.
  • Host Byte Order: Endianness that the host is using, either it is little endian or big endian.
  • ICMP: Stands for Internet Control Message Protocol. Sends error messages and control info between hosts and routers. Used by ping(to echo messages) and traceroute(to map paths).
  • ICMPv6: IPv6 version of ICMP. Combines ICMP, ARP and IGMP.
  • IGMP: Stands for Internet Group Management Protocol. For multicasting (one-to-many) systems. Uses IPv4.
  • inet_aton Stands for ASCII to Network. Converts dotted string to valid address when the address structure is passed by reference. Returns int, 1 if it is a valid dotted IPv4 address.
  • inet_ntoa Stands for Network to ASCII. Reverse of inet_aton, converts passed integer to dotted string.
  • inet_ntop Stands for Network to Presentation. IPv4 + IPv6 equivalent of inet_ntoa
  • inet_pton Stands for Presentation to Network. IPv6 compatible version of inet_aton. Takes the address family as an argument (like AF_INET or AF_INET6) as well.
  • IPv4: Uses 32-bit addressing like 192.168.1.1.
  • IPv6: Uses 128-bit addressing like 2001:0db8:85a3:0000:0000:8a2e:0370:7334.
  • listen When a socket is created, it is assumed to be a client one, an active one. The listen method converts that socket into a passive one, such that it can accept connections, making it into a server. Takes in the socket file descriptor and backlog - maximum number of pending connection queue.
  • MTU Stands for Maximum Transmission Unit. Maximum size (in bytes) of packet that can be passed through without breaking it down into smaller chunks.
  • Network Byte Order Endianness of the data sent over the network. Defined by the protocols like TCP/IP. Usually big-endian.
  • OSI Model: Conceptual model that standardizes how different computers interact with each other via networks. It has seven layers of abstraction from top to down:
    1. Application Layer
    2. Presentation Layer
    3. Session Layer
    4. Transport Layer (TCP, UDP)
    5. Network Layer (IPv4, IPv6)
    6. Datalink Layer
    7. Physical Layer
  • POSIX: POSIX stands for Portable Operating System Interface (for Unix). It defines a set of standards which if a program complies by, that program should be compilable in other operating systems as well.
  • RARP: Stands for Reverse Address Resolution Protocol. Maps MAC Address to IP Address.
  • Raw Socket: Sockets that allow you to bypass the TCP/UDP layer and provide access to lower-level network protocols.
  • RTT: Stands for Round-trip Time. Time taken by a packet to go from your computer to destination to back to your computer. Smaller for LANs but usually larger for WANs.
  • sockaddr_in IPv4 socket address structure. Consists of length, address family (usuallyAF_INET), 16-bit port, 32-bit IPv4 address.
  • sockaddr_in6 IPv6 socket address structure. Consists of length, address family (usuallyAF_INET6), 16-bit port, 32-bit flow label, 128-bit IPv6 address, 32-bit scope ID.
  • sockaddr_storage Generic container generic, big-enough structure that allows you to store socket data without worrying about the size.
  • socket Returns a socket file description once the address family, type and protocol is specified. The address family can be AF_INET, AF_INET6 etc. The type of socket can be SOCK_STREAM, SOCK_DGRAM etc. And protocol can be IPPROTO_TCP, IPPROTO_UDP etc.
  • SCTP: Stands for Stream Control Transmission Protocol. Mix of UDP and TCP. Multihoming. Reliable. Incorporates retransmission. Multiple streams.
  • Socket Pair Identifies connection between two sockets. A (local IP, local port), (remote IP, remote port)
  • TCP: Stands for Transmission Control Protocol. A type of stream socket. Makes sure that packets reach their destination. Incorporates timeouts, retransmissions. Can use either IPv4 and IPv6.
  • Three-way handshake Used by TCP to establish connection between applications.
  • TIME_WAIT: Let's say after TCP connetion termination, the final ACK from client is lost. A new connection is opened from the client but then, the lost ACK is received later. The server may interpret this as termination and this will cause an issue. To fix this, TIME_WAIT forces a pause of 2xMSL. MSL stands for Maximum Segment Lifetime i.e. how long a packet can survive in the network. With this, all ghost packets are gone.
  • UDP: Stands for User Datagram Protocol. An example of datagram socket. Not a guarantee that packets reach their destination. Can be either IPv4 and IPv6.

Concepts

TCP Connection Establishment and Termination

Three-Way Handshake

  1. The server must be ready to accept connections. This is set up with socket, bind and listen. This is called passive open.
  2. The client issues an active open by sending a 'synchronize' SYN segment (J). The SYN segment has no data, only an IP header, a TCP header and some TCP options.
  3. The server must accept the SYN segment by 'acknowledging' ACK it (J+1). The server then sends its own SYN segment (K). So, in total, the server sends its own SYN(K) and ACK(J+1) in a single segment.
  4. The client then acknowledges ACK (K+1) segment of the server.

TCP Options

  • MSS Option: Maximum Segment Size. Sent alongwith SYN segments. Advertises maximum amount of data TCP device is willing to accept. Set with TCP_MAXSEG socket option.
  • Window Size Option: Advertises how much data can be 'in-flight'. Initially set to ~64kb. But can be shifted to upto 0-14 bits (20-14) for increased bandwidth, (about 1Gb at max). Set with SO_RCVBUF socket option.
  • Timestamp option: For high-speed connections to prevent possible data corruption caused by old, delayed or duplicated segments.

TCP Connection Termination

  1. The application (let's say client) calls close. This is called active close. It sends a FIN segment (M) which means it is finished sending data.
  2. The other end (let's say server) acknowledges the segment with ACK (M+1) segment.
  3. Some time later, the server will close its socket and send FIN (N) back to client.
  4. The client will acknowledge ACK (N+1) the FIN.

SCTP Association Establishment and Termination

Four-way Handshake

  1. Server is ready in passive open state.
  2. Client sends in an initialization INIT segment with list of IP addresses, initial sequence number, initialization tag, number of outbound streams the client is requesting and number of inbound streams that it can support.
  3. The server acknowledges client's request with INIT-ACK segment and sends the list of IP addresses, initial sequence number, initialization tag, number of outbound streams the server is requesting, the number of inbound streams the server can support and a state cookie.
  4. The client echoes the server's state cookie with COOKIE-ECHO segment.
  5. The server acknowledges that the cookie is correct and establishes the association with COOKIE-ACK message.

Association Termination

SCTP does not allow half-closed associations. When one end terminates the association, the other end must stop sending data. If there is some queued data, it would be send and shutdown will take place. No concept of TIME_WAIT, as the messages are verified with verification tags. Older packets will have invalid verification tags.
